# Language packs format 3, C2 (the assistant without a model) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The controller follows `.claude/lp3-controller.md` and dispatches `lp3-implementer`, `lp3-reviewer` and `lp3-runner`.

**Goal:** A question typed in a person's words becomes one of the eight queries of `@bt-synergy/language-pack-client`, with its arguments, without a model, and the answer comes back as a card of cited pieces; measured against the gate on held-out questions in es-419 and English.

**Architecture:** Two changes in the client: Snowball stems in both search indexes, and article sections as a new row kind. Everything else goes in a new package, `@bt-synergy/language-pack-assistant`:
- a lexicon built from the maps on the device;
- the chain (rules and fixed phrases, a naive Bayes classifier per language, choices, then search);
- the card, which composes fragments from query answers;
- an `eval/` harness that runs the question sets against packs downloaded from staging.

The complement files (classifier and number words) are generated by build scripts and committed in the package.

**Tech Stack:** TypeScript (strict, the `language-pack-v3` tsconfig), Bun 1.3.3 (tests and build scripts), `bun:sqlite` in tests, the Snowball JavaScript stemmers (vendored, BSD-3-Clause), `cldr-rbnf` 49.0.0 (dev only, Unicode License).

**Spec:** `docs/superpowers/specs/2026-11-12-language-pack-assistant-c2-design.md` (decisions 1–9), and the "El asistente", "El asistente en varios idiomas", "Las secciones de los artículos y los fragmentos" and "Complementos" parts of the Consumidores tab of https://claude.ai/artifact/5Vw6P8Bm3bo51VkTRwsuPA.     - keys are sorted, so a rerun gives the same bytes.
  - `loadComplement(bytes: Uint8Array): { ok: true; value: NumbersComplement | ClassifierComplement } | { ok: false; problem: AssistantProblem }`.
    - `AssistantProblem = { code: 'E_COMPLEMENT'; kind?: string; lang?: string; message: string }`.
  - `fold(s: string): string`: NFD, no marks, lower case, `¿?¡!.,;:()«»“”"` turned into spaces, spaces collapsed.
  - `buildLexicon(maps: MapSet, tag: string, numbers?: NumbersComplement): Lexicon`.
  - `Lexicon.entities(question: string): { tokens: string[]; entities: Entity[] }`.
  - The entity type:
    ```ts
    type Entity =
      | { kind: 'ref'; book: string; chapter: number; verse?: number; verseEnd?: number; start: number; end: number }
      | { kind: 'book'; book: string; start: number; end: number }
      | { kind: 'strong'; value: string; start: number; end: number }
      | { kind: 'concept'; ids: string[]; cls: 'tw' | 'name' | 'ta' | 'topic'; start: number; end: number }
      | { kind: 'category'; value: 'person' | 'place' | 'event' | 'topic' | 'story'; start: number; end: number }
    ```
  - `Lexicon.ambiguousBooks: Map<string, string[]>`: a book code to the person ids whose name equals one of its full names (from the maps when the lexicon is built).

**The matching rules.** C0's `Dictionary.entities` is the reference; differences are listed here.
- **Books:**
  - The full name, the short name and the abbreviation of each of the 66 books in the map core, plus the code.
  - Longest alias first.
  - An abbreviation or a code counts only when a number follows, while a full name stands alone (C0's rule).
  - Book names that start with a numeral («1 Juan», «Primera de Juan», «1Jn») are matched with the leading number as part of the alias.
- **Numbers:** digits, `c:v`, `c:v-w`, and number words from `numbers.words`, longest phrase first. Fillers between them are skipped: `capitulo cap versiculo vers v verso capitulo y` and their pt and en equivalents, which are listed in `lexicon.ts`.
- **Strong:** `[GgHh]\d{1,5}`, written in upper case.
- **Concepts:**
  - Every name of `namesById` and every tA `subtitle` of the map core, folded and stemmed, matched as consecutive content words. Stop words are skipped, and the stop list per base language is in `lexicon.ts`.
  - Longest first; a token is used once.
  - The class comes from the id prefix: `tw:names/` is `name`, other `tw:` ids are `tw`, `ta:` ids are `ta`, and `per: lug: ev: tema:` are `topic`.
  - There is no edit distance (spec part 3).
  - A one-word alias shorter than 3 letters counts only when it is the article's whole title (C0's rule).
- **Book and person:** a book name that equals a person's name also yields that person as a `concept` entity over the same span.
- **Categories:** the category words of C0's `CATS`, by base language, in `lexicon.ts`.

### Task 6: Rules, fixed phrases and the classifier

**Files:**
- Create in `packages/language-pack-assistant/`:
  - `src/phrases/{es,pt,en}.json`, `src/rules.ts`;
  - `templates/{en,es,pt}.json`;
  - `src/classifier.ts`, `build/train.ts`, `complements/{es,pt,en}.classifier.json`;
  - `src/decision.ts` (moved from Task 4's declaration) and `src/decide.ts`.
- Test: `src/rules.test.ts`, `src/classifier.test.ts`, `src/decide.test.ts`

**Interfaces:**
- Consumes: `Lexicon`, `Entity` and `loadComplement` (Task 5); `Call` and `Decision` (Task 4).
- Produces:
  - `Phrases = Record<'passage' | 'concept' | 'article' | 'renderings' | 'books' | 'topics' | 'context' | 'search', string[]>`. Each entry is a folded keyword phrase matched on word boundaries; there are about 50 per language. They start from C0's `KW` and `SEARCH_KW`, and `context` phrases ask for everything about a passage («todo sobre», «ayúdame a traducir»).
  - `applyRules(tokens, entities, lexicon, phrases): { decided: Decision } | { undecided: true }`. Its order follows C0's `decide`, step 1:
    1. a reference (passage, or context with a context phrase);
    2. an ambiguous book alone, which gives `choose` of `passage` (the whole book, `ref: '<code>'`) and `concept` for each person;
    3. the `books` phrase with a Strong, concept or tA entity;
    4. the `renderings` phrase with a Strong gives `renderings {strong}`. With a tw or name concept and no Strong, it gives `choose` of `concept {id}` and `search` (C1's `renderings` takes a Strong, not a concept);
    5. a tA entity, which gives `article`;
    6. a category alone, which gives `topics`;
    7. the concept phrase with a concept;
    8. a search phrase, which gives `search` with the original text.
  - A concept entity with several ids gives `choose` over them, for the query the rule picked.
  - Classifier complement: `{ kind: 'classifier', lang, version, for, labels: QueryName[], vocab: string[], counts: number[][], totals: number[], docs: number[] }`. It is multinomial naive Bayes on word unigrams, word bigrams and character trigrams of the masked question (C0's `Classifier`, the same Laplace smoothing).
  - `train(examples: [string, QueryName][], meta): ClassifierComplement`: deterministic. The vocabulary is sorted, and so is the JSON written by `build/train.ts`.
  - `predict(model, maskedText): [QueryName, number][]`: probabilities, best first.
  - `mask(tokens, entities): string`: replaces each entity span by `ref`, `book`, `strong`, `tw`, `name`, `ta`, `topic` or `cat` (C0's `masked`).
  - `decide(question: string, ctx: { lexicon: Lexicon; phrases: Phrases; classifier?: ClassifierComplement; margin: number; labels: Labels }): Decision`. It runs rules, then the classifier (accepted when p1 − p2 ≥ `margin`, or when the first choice needs a `choose` anyway), then a `choose` of the two best when both can be filled, then `search`.
    - The first choice must have its arguments; otherwise it falls through to `search` (C0's `need`).
    - `via` says which step decided.
    - `interpretation` comes from Task 7's `interpret`; this task passes `''` and Task 7 fills it.
  - `DEFAULT_MARGIN`: set from the tune sets (Step 5), then frozen in `decide.ts` with a comment saying the tune result it came from.
- **Templates:** `templates/en.json` holds about 100 templates written once, with the slots `{ref} {book} {strong} {tw} {name} {ta} {topic} {cat}`, about 12 per query. `es.json` and `pt.json` are their translations, made by Claude; C0's `plantillas.json` may be reused where a template matches. They are slot-masked text, never real names.

  - `Fragment = { id: string; kind: 'verse' | 'note' | 'question' | 'link' | 'section' | 'concept' | 'rendering' | 'book' | 'topic'; title: string; ref?: string; concepts: string[]; length: number; cite: Answer<unknown>['cites'][number]; license?: string; link: string }`.

    - `Assistant = { ask(question: string, o?: { limit?: number }): Promise<Card>; run(call: Call, o?: { limit?: number }): Promise<Card>; problems: AssistantProblem[] }`.
    - `run` is for a chosen option or a button: the same card with no chain.
    - The default `limit` is 8.
  - **Ranking within a query** (spec part 5):
    - `passage`: the verse fragments in text order, then notes in verse and row order, then questions, then links.
    - `concept`: the `concept:` fragment, then `section:` of the article's default section when the article is installed, then `book:` cells by `count` descending.
    - `article`: the sections in the answer's order.
    - `renderings`: the renderings by count descending.
    - `books`: the cells by count descending, `none` and `zero` cells left out.
    - `topics`: as given.
    - `context`: the passage's ranking followed by the concepts.
    - `search`: the hits by score.
  - A card for a `concept` or `article` call reads `article` for the default section, so a definition question puts the definition in the first 3.
